# Ручные тест-кейсы

Тестовый пользователь должен иметь доступ к отдельной Google-таблице. После каждого кейса проверяйте ответ Telegram и соответствующие строки Sheets.

## Automated tests

Автотесты из `tests/` проверяют чистые функции без Telegram и Google Sheets:

- `test_reports.py` — месячный отчёт и StartupState;
- `test_business_logic.py` — баланс, план/факт, долги, цели и financial health;
- `test_categories.py` — нормализация и поиск дубликатов категорий;
- `test_operations.py` — суммы доходов, расходов и баланс операций.

Запуск: `python -m pytest`. CI дополнительно выполняет `python -m compileall -q app`.

## Manual regression checklist

- [ ] Доход и расход создаются через команды и inline-кнопки.
- [ ] StartupState сохраняется и не приводит к двойному учёту.
- [ ] План/факт совпадает с операциями текущего месяца.
- [ ] Платёж уменьшает долг и создаёт связанный расход.
- [ ] Пополнение увеличивает цель и создаёт связанный расход.
- [ ] Удаление обычной операции пересчитывает отчёт и диаграмму.
- [ ] Перенос категории обновляет исторические операции.
- [ ] Данные двух Telegram user ID не смешиваются.

## Smoke checklist before release

- [ ] `python -m compileall -q app` завершён с кодом 0.
- [ ] `python -m pytest` завершён без падений.
- [ ] `.env` и service-account credentials отсутствуют в Git.
- [ ] Бот запускается через `python -m app.main` и `start_bot.bat`.
- [ ] `/start`, `/add`, `/report`, `/health` и `/charts` отвечают.
- [ ] Временные PNG удаляются после отправки.
- [ ] Ошибки отсутствуют в консоли и service logs.

# V5.4 — дневной лимит

- Без активной записи `/daily_limit` сообщает, что лимит не установлен.
- При лимите 1500 и расходе 900: факт 900, остаток 600, использование 60%, зелёный статус.
- При использовании от 80% до 100% включительно показывается жёлтый статус.
- При расходе 1600 и лимите 1500 превышение равно 100, статус красный.
- После `/delete_daily_limit` запись имеет `deleted` и не участвует в расчёте.
- Операции `income` и `transfer` не входят в факт дня; все `expense` входят независимо от категории.

## V5.5 — утреннее согласование

- `09:00`, `8:30`, `23:15` принимаются и нормализуются в `HH:MM`.
- `25:00`, `12:99`, `утром`, `девять` отклоняются.
- Без override применяется месячный лимит.
- Override `active` заменяет месячный лимит.
- Override `disabled` отключает лимит только для указанной даты.
- Изменение времени заменяет scheduler job пользователя; выключение удаляет её.

## V5.6 — перенос остатка дневного лимита

- При лимите 1500, расходе 1000 и 10 оставшихся днях рекомендованный лимит равен 1550.
- При расходе ровно 1500 перенос равен 0, рекомендованный лимит остаётся 1500.
- При расходе 2000 перенос равен 0, рекомендованный лимит остаётся 1500.
- В последний день месяца перенос равен 0, даже если часть дневного лимита не потрачена.
- Если лимит на сегодня отключён через `DailyLimitOverrides`, перенос не считается.
- `/daily_limit` показывает полный блок переноса или `Перенос остатка: нет`.
- `/report` показывает короткий блок переноса только при положительном остатке дня.
- `/insights` показывает вывод о распределении остатка или сообщение, что переноса нет при превышении лимита.
