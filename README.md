# FinanceOS Java — новая разработка, версия 0.8.1

Это отдельный проект. Старый код, архивы и настройки в него не перенесены. Разработка и проверки пока идут только локально.

## Цель

Новый бот для сообщества VK на Java. Существующие финансовые данные в Google Sheets должны сохраниться. Обычный локальный запуск сохраняет новые действия только на компьютере. Отдельный тестовый VK-режим автоматически копирует состояние в тестовую копию Google Sheets; исходная таблица остаётся без записи. Основные действия в этом режиме проверены в живом VK-диалоге.

## Полный список команд VK

`/transfer` записывает внутренний перевод в историю без изменения общего баланса. `/freedom`, `/health` и `/insights` показывают описательные расчёты по текущим данным. `/morning_limit` показывает доступный лимит на момент запроса. В локальном VK-режиме после 09:00 по Москве предусмотрено однократное напоминание о зарплате или платеже, ожидающем подтверждения; реальная отправка ещё не проверена. Утренний лимит отправляется только если он включён в `UserSettings`, в первые два часа после указанного времени; в текущей резервной копии это 09:00–11:00 по Москве. `/start` показывает число ожидающих операций, `/regular_pending` показывает их коды даже после пропущенной даты. Запись появляется только после `/regular_confirm`. Текущее состояние каждого пункта — в `REQUIREMENTS.md`.

## Правила данных

- Фактический баланс и запланированные траты хранятся отдельно.
- Свободные деньги = фактический баланс − остаток ещё не оплаченных плановых расходов за текущий месяц.
- Плановый расход уменьшает фактический баланс и остаток плана на ту же сумму, поэтому не уменьшает свободные деньги второй раз. Если план исчерпан, дальнейший расход уменьшает свободные деньги.
- Незапланированные расходы уменьшают фактический баланс и через него свободные деньги. В отчёте они также показываются отдельной строкой; второй раз их не вычитаем.
- В отчёте отдельно показаны вся сумма плана и его неоплаченный остаток.
- Денежные значения — `BigDecimal`, дробная часть вводится через точку.
- Операция вводится одним сообщением `сумма, описание`; запятые внутри описания сохраняются.
- Категория не дублируется из-за разного регистра или лишних пробелов.

## Локальная проверка

Для запуска двойным щелчком откройте **`Start-FinanceOS.cmd`**. Нажмите Enter, чтобы использовать последнюю локальную резервную копию таблицы. Затем вводите команды из таблицы выше; `exit` завершает работу. Это локальная консоль, она не отправляет сообщений в VK. Демо выбирается цифрой `2`, повторное чтение Google Sheets — цифрой `3`. При обычном запуске выполняется компиляция без сетевых тестов.

Для сборки и всех проверок запустите `build.ps1` в PowerShell. Нужен JDK 21 и локальный Maven из соседней папки `toolchain`. Скрипт компилирует исходники и выполняет проверки; облачные ресурсы не использует. Зависимости скачиваются в `.m2` внутри проекта.

Для ручной проверки демо-диалога запустите `run-local-bot.ps1` без параметров. Он откроет демонстрационный баланс и план. Для дохода или расхода сначала выберите категорию, затем отправьте `сумма, описание`. Например: `/expense`, `Еда`, `1250.50, продукты`. Выход — `exit`.

Другие локальные действия: план — `/add_plan`, затем `сумма, категория`; долг — `/add_debt`, затем `название; остаток; платёж; день`; уточнение текущего долга — `/edit_debt`, затем `название; новый остаток; платёж; день`; платёж по долгу — `/pay_debt`, затем `название; сумма`; цель — `/add_goal`, затем `название; цель; ежемесячно`; пополнение цели — `/fund_goal`, затем `название; сумма`; дневной лимит — `/set_limit`, затем сумма. `/edit_debt` меняет только карточку долга и прогноз, не создаёт расход и не меняет баланс; последнее уточнение можно отменить через `/undo`. Код локальной операции виден в истории; `/delete_operation` принимает этот код. `/undo` отменяет последнее локальное изменение.

В старой таблице нет отдельной даты последнего платежа. Прогноз долга выводит срок из текущего остатка и ежемесячного платежа; последний платёж может быть меньше обычного. Если эти данные в карточке устарели, сначала уточните их через `/edit_debt`.

Отчёт за дату: `/report_date`, затем `ГГГГ-ММ-ДД`. Отчёт за период: `/report_period`, затем `ГГГГ-ММ-ДД..ГГГГ-ММ-ДД`. Если дата раньше исходного снимка баланса, показываются обороты за период без недостоверного исторического баланса.

Регулярная зарплата: `/salary_rule`, затем `сумма; день месяца; описание`. Регулярный расход: `/payment_rule`, затем `сумма; день месяца; категория; описание`. В день платежа откройте `/regular_pending`, выберите код и отправьте его после `/regular_confirm` либо `/regular_skip`. До подтверждения баланс и история не меняются; `/undo` отменяет решение. Для 31-го числа в коротком месяце используется последний день месяца.

Диаграммы строятся локально как PNG. В диалоге используйте `/charts` и выберите вид; файл сохраняется в `.local-output/charts` внутри проекта. Все пять диаграмм также можно создать из существующей таблицы без записи командой `preview-charts.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON>`.

Чтобы проверить диалог на настоящих данных **без сети и ключа**, используйте `Start-FinanceOS.cmd` и пункт `1`, либо `run-local-bot.ps1 -BackupFile <путь к локальной копии> -VkUserId <числовой ID VK>`. Чтобы сначала прочитать актуальную таблицу, используйте `run-local-bot.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON> -VkUserId <числовой ID VK>`. Операции, правила, текущий шаг диалога и последние 30 изменений для `/undo` сохраняются в `.local-state/vk-<ID VK>.json` и восстанавливаются при следующем запуске. **Google Sheets не меняется**. Если исходные данные изменились, запуск остановится, чтобы не смешать локальные записи с новым снимком.

Создать новую локальную резервную копию всех 10 рабочих листов: `backup-sheet.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON>`. Копия попадёт в `.local-output/backups`. В неё не включается ключ сервисного аккаунта. Копия от 30.10.2026 создана и проверена. Она содержит личные финансовые данные и хранится только на этом компьютере.

Она создаёт скрытый временный лист, записывает контрольное значение, читает его и удаляет лист. Проверка прошла 30.10.2026. Это ещё не сохранение операций бота в Google Sheets.

### VK с тестовой копией Google Sheets

Сначала закройте обычное окно VK-бота через Ctrl+C. Затем откройте `Start-VK-FinanceOS-TestCopy.cmd` двойным щелчком. При первом запуске укажите путь к файлу JSON сервисного аккаунта; сохраняется только путь вне проекта, содержимое ключа не копируется. Существующий токен VK используется из прежнего локального файла. В окне появится сообщение о тестовой копии. Отправьте `/start` в прежнюю беседу VK. Локальное состояние записывается сразу, а в копию переносится в фоне через несколько секунд. Если Google временно недоступен, бот продолжает работать локально и повторяет синхронизацию. При следующем запуске незавершённая передача догружается. При несовпадении двух независимо изменённых копий бот остановится для ручной сверки, не затирая данные. Не запускайте одновременно обычный и тестовый VK-режим. Исходные десять листов и исходная таблица не меняются: новые состояния хранятся в отдельном скрытом листе тестовой копии.

Для перезапуска работающего VK-бота в том же окне введите `R` и нажмите Enter. Бот завершит текущее обращение к VK (при задержке соединения это может занять до 25 секунд) и запустится снова в том же режиме; путь к ключу и токен повторно вводить не нужно. После обычной остановки окно предложит `R` для повторного запуска или `Q` для закрытия. Это работает в обоих файлах запуска VK. В локальной консоли `Start-FinanceOS.cmd` сначала введите `exit`, затем выберите `R` в том же окне.

Живой тест 30–31.10.2026: `/start` и `/report` ответили, пробный расход и `/undo` подтвердились, после перезапуска `/report` снова ответил. Также пришли `/history_all` и изображение `/chart_expenses`. Отдельная команда `verify-copy-restore.ps1 -KeyFile <путь к JSON>` скачивает состояние из тестовой копии только во временную папку, проверяет совместимость с исходной резервной копией и удаляет временные файлы; проверка прошла.

Для прямой проверки сообщений в VK откройте `Start-VK-FinanceOS.cmd`. Если токен ещё не сохранён, файл запуска попросит вставить его скрытым вводом и сохранит в `%LOCALAPPDATA%\FinanceOS\vk-token.txt` вне проекта. Скрипт берёт последнюю локальную копию таблицы и слушает сообщения сообщества с этого компьютера; компьютер должен оставаться включённым. Токен не нужно отправлять в чат. В настройках сообщества должны быть включены сообщения и события `message_new` для Long Poll. Бот принимает сообщения от профиля `564689957` в личном диалоге или в закреплённой беседе `2000000001`. Перед каждым ответом в беседу он запрашивает её участников у VK и отправляет финансовые сведения только если там остались этот профиль и сообщество `242685493`. Кнопки размещаются по две в строке; если VK отвергнет клавиатуру, бот повторит отправку текста со списком команд. При работе создаётся короткий журнал `.local-output/logs/vk-local.log`: время подключения, число входящих событий, пропущенные команды и результат отправки; токен, текст сообщений и суммы не записываются. Для нестандартного расположения токена доступна команда `run-vk-local.ps1 -TokenFile <путь к файлу> -AllowedChatPeerId <ID беседы>`.

## Следующие этапы

1. Проверить запись и отмену всех видов изменений на отдельной копии Google Sheets.
2. Проверить прямой локальный запуск Java-версии в реальном VK после подготовки файла токена; протестировать сообщения, изображения, напоминания, повторные события и восстановление после сбоя. В коде есть сохраняемый входящий буфер событий и локальный Long Poll.
3. Добавить автоматическую отправку утреннего лимита и провести пользовательскую приёмку всех сценариев.
4. После завершения кода подготовить запуск в Yandex Cloud Functions по событиям VK и перенести актуальные данные. Порядок и ограничения — в `CLOUD_DEPLOYMENT.md`.

Отправка текста и изображения диаграммы расходов проверена в реальном сообществе VK. Формат запросов сверялся с [официальной схемой VK API](https://github.com/VKCOM/vk-api-schema).

Названия листов и полей существующей таблицы записаны в `SHEET_SCHEMA.md`.

Для проверки реальной таблицы только на чтение подготовлена команда `financeos.data.LocalSheetCheck`. Ей нужны ID таблицы и путь к **новому** ключу сервисного аккаунта. Ключ не копируется в проект и не печатается; проверка выводит только число строк на каждом листе. Проверка с новым ключом прошла 30 октября 2026 года: структура всех десяти рабочих листов совпала. Финансовые значения не выводились.

Повторить проверку можно через `check-sheet.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON>`. Сервисному аккаунту для этого достаточно права просмотра таблицы. Передавать содержимое JSON в чат не нужно.

Локальный черновик отчёта формируется командой `preview-report.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON>`. Она читает таблицу, считает баланс и планы, печатает суммы только в локальную консоль и не меняет данные. Фактический баланс на 30 октября 2026 года владелец подтвердил. По уточнению от 31 октября свободные деньги рассчитываются после резервирования только ещё не оплаченной части плана.

Историю операций за день или период можно посмотреть локально через `preview-history.ps1 -SpreadsheetId <ID> -KeyFile <путь к JSON> -From ГГГГ-ММ-ДД -Through ГГГГ-ММ-ДД`. Вывод содержит суммы и описания операций, поэтому запускайте его только там, где эти данные можно показывать.

Версия 0.8.2: кнопка «Список команд» в главном меню, /help и /commands показывают полный перечень, сохраняя текущий шаг ввода.


### Пополнение целей (0.11.3)

Пополнение цели уменьшает фактический баланс и увеличивает накопления цели на ту же сумму. Оно учитывается как расход, поэтому пересчитываются отчёты, свободные деньги и аналитика. Изменение суммы и отмена пересчитывают обе стороны. Старые операции, явно связанные с целью, учитываются аналогично; начальные накопления из исходной таблицы повторно не списываются.

## Интерфейс 0.12.0

- `/start`: расход, доход, отчёт, все операции, планы, дополнительные разделы и помощь.
- `Все операции` и `Изменить`: сегодня, вчера, текущий месяц, произвольный период или вся история. Поиск по категории, точной сумме или части комментария без учёта регистра. Фильтры можно сочетать через возврат к поиску.
- После изменения сохраняются фильтры и страница, включая перезапуск. Если операция перестала соответствовать поиску, она исчезает из результата. Если страниц стало меньше, открывается последняя существующая.
- При листании облачный бот обновляет прежнее сообщение. Если VK отклонит правку сообщения, отправляет новую страницу. Запрос к облаку при нажатии остаётся необходимым.
- Суммы и пояснения разделяет `·` в обоих направлениях. 🟢/🔴/⚪ дополняют знак суммы. Снижение расходов при сравнении месяцев отмечается зелёным, снижение доходов красным.
- Сравнение показывает два последних полных календарных месяца по записанным операциям.
- Команды сохранены в разделе «Помощь», включая `/history_all` и `/edit_operations`.

Формат состояния 6 читает прежние версии 1–5. Он добавляет только настройки просмотра. Денежные записи, связи с долгами/целями, отмена и защита от повторов сохраняются. Старые версии программы, понимающие только формат 5, после обновления использовать нельзя.

## Удаление операций 0.12.1

Путь: «Изменить» → период и поиск → операция → «Удалить» → «Да, удалить». В меню добавления удаления больше нет. Из «Все операции» можно открыть изменение и ту же карточку. Команда `/delete_operation` оставлена как совместимый вход в список, без немедленного удаления.

Подтверждение показывает дату, сумму, категорию и комментарий. Отмена и «Назад» не меняют данные. После удаления сохраняются поиск и страница (при уменьшении числа страниц выбирается последняя существующая). «Отменить» восстанавливает операцию и связанные остатки, в том числе после перезапуска.

Удаление исключает запись из расчётов и истории, сохраняя её для отмены. Для записей, связанных с долгом или целью, пересчитывается соответствующий остаток. Старые операции из исходного снимка тоже доступны. Снимок не перезаписывается. Удаление подтверждённой регулярной операции само по себе не возвращает её в очередь подтверждения.

Состояние формата 7 хранит удалённые ID и в снимках отмены. Старые форматы 1–6 читаются. После перехода на формат 7 нельзя запускать старую версию приложения, которая его не понимает.

## Кэш и автотесты 0.12.2

В памяти обработчика кэшируются проверенные копии объектов, разобранный исходный снимок и неизменяемое состояние приложения. Перед использованием объекта проверяется ETag через Object Storage. При внешнем изменении приходит новая копия. При ошибке проверки старый баланс не выдаётся как свежий. Кэш не заменяет сохранение, не кеширует состав беседы VK и исчезает при завершении процесса. Подробности: [CACHING-v0.12.2.md](CACHING-v0.12.2.md).

Для изучения тестов:

- [Подробный план покрытия проекта](docs/testing/PROJECT_TEST_PLAN.md).
- [Пошаговое руководство с упражнениями](docs/testing/HOW_TO_WRITE_TESTS.md).
